01 — Data Engineering / MLOps

TripAdvisor Restaurants Pipeline

AirflowPySparkKafkaSpark StreamingFastAPIReactDockerPython

Overview

Full-stack data system built around 1M+ rows of European TripAdvisor restaurant data. Goes end-to-end: from raw CSV to a live web app where users can search for restaurants by cluster similarity and watch real-time ML scoring in their browser.

Architecture

  • 5-stage Airflow DAG: Extract → Clean → EDA → Preprocess (normalization, OHE/label encoding by cardinality, incremental PCA) → Stream to Kafka — all in 50k-row chunks, no full dataset in memory
  • PySpark ML KMeans with automatic K selection via silhouette scoring across K = 10–80; model cached to avoid redundant recomputation
  • Dual Spark Structured Streaming consumers: streaming_filter.py (fast filter, no ML) and streaming_score.py (centroid distance + timestamped cluster assignments)
  • FastAPI backend + React/Vite frontend — restaurant search with cosine-similarity recommendations within clusters, and a live tab with Server-Sent Events pushing classifications in real time
  • Priority queue for immediate model scoring of user-selected restaurants

Key challenge

The ETL pipeline can't load 1M+ rows at once — every stage processes data in 50k-row chunks, including the incremental PCA and encoding steps, which required careful state management across iterations. On the streaming side, the two-consumer architecture separates latency-sensitive display from compute-heavy ML scoring without blocking either path.

02 — Streaming / Distributed

Real-Time Hashtag Trending

PySparkDStreamsWindowingPython

Overview

Distributed real-time trending analysis using PySpark DStreams. Connects to a live TCP tweet feed, filters for US-only content, and maintains a 5-minute sliding window with 10-second slide intervals to rank hashtags continuously.

The interesting part

The naive approach — recomputing the full window on each slide — is O(window size). Instead, the pipeline uses inverse reduction functions (invFunc): on each slide, only new arrivals are added and expired tweets are subtracted. This makes each update O(slide interval), not O(window size). A 5-minute window with 10-second slides is 30x cheaper per update.

Stack decisions

  • DStreams over Structured Streaming — lower-level, but invFunc is not available in the Structured API
  • TCP socket source simulates a real-time feed for local testing

06 — Statistical Modeling / ML

Forest Fire Prediction

RGAMGLMmgcvtidyverse

Overview

Regression study predicting burned area in Montesinho Natural Park from meteorological and fire index covariates. The dataset has severe zero-inflation (many fires burn near-zero area) and extreme right skew — OLS is the wrong tool from the start.

Model progression

  • OLS baseline — exposed heteroscedasticity and zero-inflation problems
  • Gamma GLM — handles positive skew and non-constant variance
  • Inverse Gaussian GLM — heavier tail, better fit for extreme values
  • GAM with smoothing splines via mgcv — final model, best fit

Key finding

GAMs revealed non-linear threshold effects for temperature and Drought Code that were invisible to OLS and GLMs — above certain thresholds, burned area increases sharply. This is a physical phenomenon the parametric models couldn't capture. Model choice here is a scientific decision, not a default.

08 — Statistical Inference

Whitehead Sample Size Analysis

RMLEScore TestMonte CarloR Markdown

Overview

Implementation of Whitehead's (1983) unified theory for sample size determination in clinical trials. The goal: find the minimum sample size to detect a deviation from a baseline event probability of p₀ = 0.003 with Type I error α = 0.025 and 80% power.

Methods

  • Mathematical derivation of Fisher Information and Score Statistics for binomial distributions
  • Whitehead's formula applied to get the theoretical sample size
  • Parametric tests: Chi-Square and Exact Binomial for validation
  • Wilcoxon Rank-Sum Test as a non-parametric alternative when normality assumptions break down
  • Monte Carlo simulation: binomial draws used to compare theoretical vs empirical Type I error rates

Key finding

At p = 0.003, asymptotic approximations (Score Test) are computationally efficient but require sufficiently large n to be valid — small probabilities push the asymptotics hard. The Exact Binomial test provides a ground truth check, and the Wilcoxon confirms robustness when the normality assumption is questionable.

09 — Time Series / Forecasting

Time Series Analysis with SARIMA

PythonSARIMAstatsmodelspandasKaggle

Overview

Analysis and forecasting of four different time series using SARIMA models. The workflow for each series follows the Box-Jenkins methodology: identify, estimate, and diagnose — repeated until the residuals behave like white noise.

Methodology

  • Stationarity testing with ADF and KPSS — both tests used together since they have opposite null hypotheses
  • Time series decomposition into trend, seasonal, and remainder components
  • ACF and PACF plots to determine candidate AR, MA, and seasonal orders
  • Model selection via AIC and BIC across a grid of SARIMA(p,d,q)(P,D,Q)s candidates
  • Residual diagnostics: Ljung-Box test, ACF of residuals, Q-Q plots to validate white noise assumption

What makes it interesting

Working with four structurally different series forces you to make different modeling decisions for each one — different differencing orders, different seasonal periods, different levels of heteroscedasticity. The project is as much about diagnosing what's wrong with a model as it is about fitting one.
